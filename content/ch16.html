16.1 Core Java

Question Answer
JDK vs JRE vs JVM? JVM (Java Virtual Machine) runs bytecode; JRE (runtime) = JVM + libraries; JDK (dev kit) = JRE + dev tools (javac, jcmd…). [1.1]
Is Java pass-by-value? Always. For objects, the reference is copied, not the object. [1.6]
Why is String immutable? So it can be pooled and shared, kept secure, cache its hashCode, and be thread-safe. [1.4]
== vs equals? == compares references (or primitive values); equals compares logical content. [1.12]
equals/hashCode contract? Equal objects must have equal hash codes; equal hash codes do not mean equal objects. [1.12]
Integer cache range? −128 to 127, when using Integer.valueOf (and autoboxing). [1.2]
StringBuilder vs StringBuffer? Same methods; StringBuffer is synchronized, so slower. Use StringBuilder. [1.5]
Interface vs abstract class? Interface: a contract for many unrelated classes, no state. Abstract class: shared state and code for related classes. [1.10]
Overloading vs overriding? Overloading: chosen at compile time by parameters. Overriding: chosen at runtime by the actual object type. [1.9]
Can static methods be overridden? No, they are hidden; the call depends on the reference type, not the object. [1.9]
final on variable/method/class? Variable: assign once / method: can't override / class: can't subclass. [1.7]
Checked vs unchecked exceptions? Checked: must declare or handle. Unchecked: RuntimeException subclasses, no need. [1.15]
Does finally always run? Yes, except on System.exit or a JVM crash. Never return from finally. [1.15]
try-with-resources? Closes AutoCloseable resources automatically, in reverse order; extra exceptions are kept as "suppressed". [1.15]
Type erasure consequences? Generic types vanish at runtime, so: no primitives as type args, no new T(), no generic arrays, no instanceof on parameterised types. [1.16]
PECS? Producer extends, consumer super: read from ? extends T, write to ? super T. [1.16]
How to make a class immutable? Final class, private final fields, no setters, defensive copies of mutable fields. [1.14]
Comparable vs Comparator? Comparable: natural order inside the class. Comparator: outside order you can combine. [1.13]
Why not a - b in comparators? It can overflow and give the wrong sign; use Integer.compare. [1.13]
Shallow vs deep copy? Shallow shares nested objects; deep copies them too. Prefer copy constructors over clone. [1.14]

16.2 Collections

Question Answer
HashMap default capacity and load factor? 16 and 0.75, so it resizes at 12 entries. [2.4]
When does a HashMap bucket treeify? When a chain reaches 8 and the table has ≥ 64 slots; turns back into a list at 6. [2.4]
Why power-of-two capacity? Index is a fast (n-1) & hash, and on resize each entry stays or moves by exactly n (one bit decides). [2.4]
HashMap worst-case lookup in Java 8+? O(log n), because big buckets become trees. [2.4]
Null keys in HashMap / ConcurrentHashMap / TreeMap? One allowed / none / none (it needs to compare keys). [2.4, 4.9]
ArrayList growth? Grows 1.5× by copying into a bigger array (Arrays.copyOf). [2.2]
ArrayList vs LinkedList? ArrayList: fast index access and CPU-cache friendly. LinkedList: O(1) insert only at a node you already hold. Pick ArrayList almost always. [2.2, 2.3]
What backs HashSet? A HashMap whose values are a dummy object. [2.7]
TreeMap complexity and structure? A red-black (self-balancing) tree, O(log n), with NavigableMap methods like floorKey/ceilingKey. [2.6]
LinkedHashMap access order? new LinkedHashMap<>(cap, 0.75f, true) + override removeEldestEntry → an LRU (least recently used) cache. [2.5]
Stack/queue class to use? ArrayDeque. [2.8]
Is PriorityQueue iteration sorted? No; only the head is guaranteed to be the minimum. [2.9]
Fail-fast vs fail-safe iterators? Fail-fast throws CME (ConcurrentModificationException) if the collection changes; fail-safe iterates a snapshot or weakly consistent view. [2.10]
Remove while iterating? Use iterator.remove() or removeIf. [2.10]
Arrays.asList gotcha? Fixed size (no add/remove); with an int[] you get List<int[]>. [2.11]
unmodifiableList vs List.copyOf? A read-only view of the original vs an independent immutable copy. [2.11]
Sort algorithms used? Primitives: dual-pivot quicksort; objects: TimSort (stable — equal items keep their order). [2.11]

16.3 Java 8–21

Question Answer
Functional interface? Exactly one abstract method; a lambda can be used for it. [3.1]
Function vs Supplier vs Consumer vs Predicate? T→R, ()→T, T→void, T→boolean. [3.1]
Intermediate vs terminal ops? Intermediate: lazy, return a stream. Terminal: actually run the pipeline. [3.2]
map vs flatMap? One-to-one vs one-to-many, flattened into one stream. [3.2]
Reuse a stream? No — you get IllegalStateException. [3.2]
Parallel streams risk? They use the shared common ForkJoinPool, so blocking calls starve it; overhead is not worth it for small data. [3.4]
toMap duplicate keys? IllegalStateException, unless you pass a merge function. [3.3]
groupingBy with counting? groupingBy(f, Collectors.counting()) → Map. [3.3]
orElse vs orElseGet? orElse always builds the default (eager); orElseGet builds it only if needed (lazy). [3.5]
Where not to use Optional? Fields, method parameters, collections. [3.5]
Record features? Final class, immutable fields, auto-generated accessors/equals/hashCode/toString, compact constructor for checks. [3.7]
Sealed classes? Limit which classes can extend it with permits; switches can then cover all cases. [3.8]
Switch expression yield? Returns a value from a block { } arm of a switch expression. [3.9]
Virtual threads? Cheap threads scheduled by the JVM that step off the OS thread during blocking I/O; for I/O-bound concurrency. [4.12]
Pinning? A virtual thread can't step off its OS thread (inside synchronized or native code) in Java 21. [4.12]
Instant vs LocalDateTime? A point in time in UTC vs a date-time with no time zone. [3.6]

16.4 Concurrency

Question Answer
start() vs run()? start() runs the code on a new thread; run() runs it on the current thread. [4.1]
sleep vs wait? sleep keeps its locks; wait releases the monitor and needs notify to wake. [4.5]
Why wait in a loop? Threads can wake up for no reason (spurious wakeups), and the condition may have changed. [4.5]
volatile guarantees? Visibility + ordering, but not atomicity (count++ is still unsafe). [4.6]
happens-before examples? Unlock→next lock, volatile write→read, Thread.start, Thread.join, submitting to an executor. [4.6]
Why volatile in DCL singleton? In DCL (double-checked locking), it stops other threads seeing a half-built object. [4.6]
ReentrantLock over synchronized? tryLock with timeout, can be interrupted, fairness option, multiple Conditions. [4.7]
CAS and ABA? CAS = atomic compare-and-swap. ABA (value changes A→B→A unnoticed) is fixed with stamped references. [4.8]
LongAdder vs AtomicLong? LongAdder spreads updates over many cells → faster when many threads update; reading the sum is slower. [4.8]
ThreadPoolExecutor admission order? Core threads first → then queue → then extra threads up to max → then reject. [4.3]
Problem with newFixedThreadPool? Its queue has no limit → memory blows up under load. [4.3]
Rejection policies? Abort, CallerRuns, Discard, DiscardOldest. [4.3]
Pool size I/O-bound? cores × (1 + wait time / compute time). [4.3]
CHM in Java 8? ConcurrentHashMap: CAS on empty bins, synchronized on the bin's head node, lock-free reads, threads help with resizing. [4.9]
containsKey-then-put race fix? Use one atomic call: putIfAbsent / computeIfAbsent / merge / compute. [4.9]
CountDownLatch vs CyclicBarrier vs Semaphore? Wait for N events (one-shot) / N threads wait for each other (reusable) / limit how many run at once. [4.10]
thenApply vs thenCompose vs thenCombine? Map the value / flatMap another async call / zip two futures together. [4.11]
CompletableFuture default executor problem? It uses the shared common pool — pass your own executor for I/O. [4.11]
Deadlock conditions and prevention? Mutual exclusion, hold-and-wait, no preemption, circular wait; prevent with fixed lock order or tryLock. [4.13]
How to detect deadlock in prod? Take a thread dump; look for "Found one Java-level deadlock". [4.13]
ThreadLocal risk? Values leak into the next request on a pooled thread; always call remove(). [4.15]

16.5 JVM

Question Answer
Heap generations? Young (Eden, S0, S1 survivor spaces) and Old. [5.3]
PermGen replaced by? Metaspace (in native memory) in Java 8. [5.2]
GC roots? Starting points for GC: thread stacks, static fields, JNI (native code) references, active threads. [5.4]
Default GC since Java 9? G1. [5.5]
G1 vs ZGC? G1: heap split into regions, aims for a pause-time target. ZGC: compacts while the app runs, pauses under 1 ms. [5.5]
StackOverflowError cause? Recursion that goes too deep. [5.2]
Memory leak causes in Java? Static caches, listeners never removed, ThreadLocals, inner classes holding the outer object, unclosed resources, keys changed after insert. [5.7]
Tools for high CPU? top -H → convert thread ID to hex → find that nid in a thread dump; or JFR (Java Flight Recorder) / async-profiler. [5.8]
Tools for OOM? For OutOfMemoryError: -XX:+HeapDumpOnOutOfMemoryError + MAT (Memory Analyzer) dominator tree; compare heap histograms over time. [5.9]
Class loader delegation? A loader asks its parent first; order is bootstrap → platform → app. [5.1]
JIT tiers? Interpreter → C1 (quick compile) → C2 (optimised compile), with deoptimisation if assumptions break. [5.10]
Container heap sizing? -XX:MaxRAMPercentage≈75 (heap = about 75% of the container's memory). [5.11]

16.6 Spring Boot and JPA

Question Answer
@SpringBootApplication = ? @Configuration + @EnableAutoConfiguration + @ComponentScan. [6.9]
Why constructor injection? Final fields, clear dependencies, easy to test, circular dependencies fail at start-up. [6.2]
@Component vs @Bean? @Component: a class found by scanning. @Bean: a factory method inside a @Configuration class. [6.3]
Bean scopes? singleton, prototype, request, session, application. [6.5]
Prototype in singleton fix? Get a fresh one each time via ObjectProvider / @Lookup / a scoped proxy. [6.5]
Bean lifecycle order? Construct → inject → Aware callbacks → BPP (BeanPostProcessor) before → @PostConstruct → BPP after (proxy made here) → @PreDestroy. [6.6]
How does auto-configuration work? Starters bring conditional config classes; they step back if you define the bean yourself. [6.9]
Self-invocation problem? Calling a method from the same class skips the proxy → no @Transactional/@Async/@Cacheable. [6.7]
JDK proxy vs CGLIB? JDK proxy: based on an interface. CGLIB: makes a subclass (Boot's default). [6.7]
Property precedence top? Command-line args > environment variables > profile files > application.yml. [6.8]
Filter vs Interceptor? Filter: Servlet level, before Spring. Interceptor: Spring MVC level, knows which handler runs. [7.5]
Global error handling? @RestControllerAdvice + @ExceptionHandler → return a ProblemDetail. [7.4]
N+1 fixes? Fetch join, @EntityGraph, batch fetch size, DTO (plain data object) projection. [7.10]
LazyInitializationException? A lazy field is read after the session closed; load it inside the transaction; turn off OSIV (Open Session In View). [7.11]
Dirty checking? Changes to managed entities are UPDATEd automatically at flush. [7.9]
Default fetch types? ToOne is EAGER, ToMany is LAZY — make ToOne LAZY too. [7.8]
@Transactional default rollback? Only on unchecked exceptions and Errors, not checked exceptions. [7.12]
REQUIRED vs REQUIRES_NEW vs NESTED? Join existing or create one / always a separate new one / a savepoint inside the current one. [7.13]
Isolation levels? Read Uncommitted, Read Committed (Postgres default), Repeatable Read (MySQL default), Serializable. [7.14]
Optimistic vs pessimistic locking? Optimistic: @Version column + retry on conflict. Pessimistic: SELECT FOR UPDATE locks the row. [7.15]
Prevent overdraw atomically? UPDATE ... SET bal = bal - p WHERE id=? AND bal >= p and check the updated row count. [7.15]
IDENTITY vs SEQUENCE ids? IDENTITY turns off Hibernate batch inserts; SEQUENCE allows them. [7.16]
ddl-auto in prod? Set to validate, and change schema with Flyway/Liquibase migrations. [7.16]
JWT validation checks? Signature, exp (expiry), iss (issuer), aud (audience). [8.2]
When CSRF needed? For cookie-based browser sessions; not for APIs using bearer tokens. [8.1]
@WebMvcTest vs @SpringBootTest? Only the web layer vs the full application context. [8.4]
Why Testcontainers? Tests run against a real DB/Kafka in Docker, so behaviour matches production. [8.4]
Kafka consumer idempotency? Safe to process twice: store processed event IDs (unique key) in the same transaction as the effect. [8.5]
Cache-aside write rule? Update the DB first, then evict (delete) the cache key. [8.6]
Circuit breaker states? Closed → Open → Half-open. [8.7]
Scheduled job once per cluster? ShedLock / Quartz in cluster mode / a Kubernetes CronJob. [8.8]

Composition over inheritance — why? Less tight coupling, can change behaviour at runtime, no fragile base class. [9.1]
Strategy vs State? Strategy: the client picks the algorithm. State: the object moves itself between states. [9.17, 9.19]

Factory vs Builder? Factory decides which class to create; Builder builds one complex object step by step. [9.9, 9.10]

16.8 HLD

Question Answer
1M requests/day ≈ ? QPS About 12 QPS (queries per second), since a day ≈ 10⁵ seconds. [11.2]
99.9% vs 99.99% downtime/year? About 8.8 hours vs about 53 minutes. [11.3]
L4 vs L7 load balancer? L4 routes on TCP/IP info only; L7 understands HTTP (paths, headers). [11.4]
Cache stampede fixes? Let only one request reload (single-flight or lock), add random jitter to TTLs, serve stale data while refreshing. [11.5]
Cache penetration fix? Cache "not found" results too; or use a Bloom filter to reject unknown keys. [11.5]
Composite index rule? Works from the leftmost column; put equality columns before range columns. [12.5]
Quorum condition? R + W > N (read replicas + write replicas > total replicas). [11.8]
Replication lag anomaly fix? Read-your-writes: read from the leader right after a user writes. [11.8]
Good shard key? Many distinct values, spreads load evenly, matches the main way you query. [11.9]
CAP in one line? When the network splits, you must choose consistency or availability. [11.10]
PACELC adds? Else (no split): choose low latency or consistency. [11.10]
Consistent hashing benefit? Adding/removing a node moves only ~1/N of keys; virtual nodes even out the load. [11.11]
Queue vs log? Queue: message deleted once acknowledged, spreads work. Log: messages kept, can be replayed, ordered per partition. [11.12]
Kafka ordering? Only within one partition; pick the message key with that in mind. [11.13]
Kafka max consumer parallelism? The number of partitions. [11.13]
No-loss Kafka config? acks=all, replication factor 3, min.insync.replicas=2, idempotent producer. [11.13]
Exactly-once across systems? Deliver at-least-once + make consumers idempotent (safe to process twice). [11.12]
Dual-write fix? Transactional outbox table + a relay or CDC (change data capture) to publish. [11.15]
Saga types? Choreography (services react to events) vs orchestration (one coordinator directs). [11.15]
URL shortener ID generation? Hand out pre-allocated ID ranges to servers + encode in base62. [13.1]
Feed fan-out choice? Push for normal users, pull for celebrities (hybrid). [13.4]
Chat delivery transport? WebSockets + a registry of who is connected where + push notification if offline. [13.5]
Leaderboard store? Redis sorted sets (ZINCRBY, ZREVRANGE, ZREVRANK). [13.9]
Typeahead structure? A trie with the top-K suggestions precomputed at each node; sharded and cached. [13.10]
Nearby drivers index? Geohash/Redis GEO, a quadtree, or H3 hexagon cells. [13.13]
Payments correctness keys? State machine, idempotency at every step, double-entry ledger, reconciliation. [13.8]
SLI vs SLO vs SLA? What you measure / your internal target / the promise in the contract. [11.20]

16.9 Databases and SQL

Question Answer
LEFT JOIN filter trap? A condition on the right table in WHERE turns it into an INNER JOIN; put it in ON. [12.1]
NOT IN vs NOT EXISTS? NOT IN returns nothing if the subquery has a NULL; use NOT EXISTS. [12.1]
Nested loop vs hash vs merge join? Small outer + indexed inner / large unsorted with equality / both inputs already sorted. [12.1]
ROW_NUMBER vs RANK vs DENSE_RANK? 1,2,3,4 / 1,2,2,4 / 1,2,2,3. [12.2]
Top N per group? DENSE_RANK() OVER (PARTITION BY g ORDER BY x DESC) in a subquery, then filter <= N. [12.2]
Running total? SUM(x) OVER (PARTITION BY k ORDER BY t ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW). [12.2]
Previous row value? LAG(x) OVER (ORDER BY t). [12.2]
Gaps and islands trick? date − ROW_NUMBER() stays the same for every row in a consecutive streak. [12.2]
Recursive CTE use? Hierarchies: manager chains, category trees. [12.3]
SQL logical evaluation order? FROM → WHERE → GROUP BY → HAVING → window → SELECT → DISTINCT → ORDER BY → LIMIT. [12.4]
B+ tree lookup cost? About 3–4 page reads even for a billion rows; leaves are linked, so ranges are fast. [12.5]
Clustered vs non-clustered index? Clustered: the rows themselves are stored in key order (only one per table). Non-clustered: a separate structure pointing to rows. [12.5]
Covering index? Has every column the query needs (via INCLUDE) → no trip to the table. [12.5]
Why is my index not used? Function/cast on the column, leading wildcard (LIKE '%x'), filter matches too many rows, wrong column order, outdated statistics. [12.5]
Reading EXPLAIN — first check? Estimated vs actual row counts; full scans where a filter is selective; sorts spilling to disk. [12.6]
MVCC? Multi-version concurrency control: writers create new row versions, readers see a snapshot, so reads and writes don't block each other. [12.7]
SQL Server READ COMMITTED difference? It uses locks, unless READ_COMMITTED_SNAPSHOT is turned on. [12.7]
Avoid DB deadlocks? Touch rows in the same order, keep transactions short, good indexes, single atomic statements, retry the victim. [12.7]
Write skew? Two transactions read the same condition, then write different rows, breaking a rule together; needs SERIALIZABLE or FOR UPDATE. [12.7]
FOR UPDATE SKIP LOCKED use? Many workers each pick different rows from a job or outbox table, without waiting on each other. [12.7]
Partitioning vs sharding? Partitioning: split a table inside one DB (skip partitions, drop old data). Sharding: split across servers (scale writes). [12.8]
Row store vs column store? Row store for OLTP (single-row reads/writes); column store for OLAP (big scans and aggregates). [12.9]
RabbitMQ vs Kafka? RabbitMQ: routing, ack and TTL per message, work queues. Kafka: very high throughput, messages kept and replayable. [11.12]
